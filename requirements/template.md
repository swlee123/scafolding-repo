# [Feature / initiative name]

## Problem
What problem exists today, from the user's point of view. Be specific about who is affected and how.

## Desired outcome (working backwards)
Describe the end state as if it already exists — what can the user do, what's different, what's better? Derive everything below from this; don't start from the technology or the existing codebase's shape.

## Success criteria
How will we know this worked? What's measurable or observably true once it ships?

## Requirements
What must be true/built for the desired outcome to exist — functional and non-functional. Derived from the outcome above, not listed from habit.

## Key questions
- **Who is this for, specifically?**
- **What's the smallest version that tests the core bet?**
- **What has to be true for this to work? What are we assuming?**
- **What's the biggest risk, and what would make this fail?**
- **What are we explicitly choosing not to do?**

## Open questions
Anything unresolved before implementation starts.
